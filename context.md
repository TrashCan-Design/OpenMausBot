1. What the project is
Repository: https://github.com/TrashCan-Design/OpenBot (owner account: the GitHub organization TrashCan-Design).
It is a customized fork of the upstream project https://github.com/milind-soni/OpenMausBot. The product was renamed from OpenMausBot to OpenBot in the fork (commit 99a82695 "Refactor fork as OpenBot and publish Windows update workflow").
OpenBot is an Electron desktop app plus a local Node server that runs AI engines and agent "bots". It runs locally on Windows. Bots can be given a "computer" to operate (local computer, local VM, Cloud Computer, or a Self-hosted VPS).
Tooling (CONFIRMED): pnpm workspace, TypeScript, Vitest 4.1.11, oxlint --deny-warnings, Node 24 required (CI uses Node 24; the audit sandbox had Node 22), Electron builder for Windows, a Cloudflare control-plane workspace (@openmausbot/control-plane, workerd tests), a connector package, a docs site under apps/docs.
Typecheck is tsc -b && tsc -p tsconfig.server.json. Locale tooling: pnpm i18n:check and node scripts/generate-locale.mjs --record-hashes (16 languages, src/locales/source-hashes.json).
Core architecture intent (USER-STATED, repeated in several messages)
OpenBot and its agent/model execution stay local on Windows.
The VPS (a GCP VM, about 8 GB RAM, Linux) is only a remote desktop service that bots connect to and operate. It does not host the OpenBot agent runtime, models or orchestration.
The VPS is reached through the existing Cloud Computer, then Self-hosted VPS, functionality using standard SSH, Docker, a VPS IP address and an SSH key.
Do not use GCP or the gcloud CLI. Existing GCP Console workflows are acceptable for manual cloud setup.
Security model to preserve: SSH private and restricted; Docker, VNC and desktop control ports never public; no unauthenticated remote desktop; no secrets in logs, fixtures, docs or release artifacts.
2. Shared VPS Desktop feature (the main development effort)
Goal (USER-STATED): add a Shared VPS Desktop mode to the existing Self-hosted VPS feature, without replacing or breaking the existing Per-Bot VPS mode.

Per-Bot VPS: existing behavior and lifecycle, one desktop per bot.
Shared VPS Desktop: one persistent desktop shared by multiple bots, with exclusive write control by one bot or user at a time, a queue or lock, ownership and lease tracking, read-only observation by authorized bots, session-bound manual Take Control, recovery after interruptions, and protection against one bot destroying another's environment.
Lifecycle rule: the shared desktop is not tied to any single bot's lifecycle. Deleting, stopping or recreating one bot must not delete the shared container, shared files, other bots' access, or reset the browser state.
Race conditions the user listed for review: two bots requesting at once, owner disconnecting, owner crashing or timing out, queued bot cancelled, desktop restarting, VPS unreachable, stale lock or lease, bot deleted while desktop active, concurrent state changes.
Capabilities the user's later prompt says already exist: Cua computer-use tools (Cua Driver 0.37.0), screenshots, a desktop viewer, protection against uncertain remote mutations (a timed-out mutation may have executed and must not be replayed), Grok Bot import, Windows packaging with GitHub Release publication for in-app updates.
