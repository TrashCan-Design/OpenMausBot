1. EXECUTIVE SUMMARY & CORE DIAGNOSIS
--------------------------------------------------------------------------------
When a user issues the instruction:
"Can you open firefox and wikipedia and in it search for worldwar 1"

In standard OpenBot environments, the task takes over 6 to 8 minutes (360–480s)
and often times out or fails completely.

This severe latency is NOT caused by model network latency or server CPU load.
Instead, it is the product of eight compounding architectural bottlenecks:

1. Surface Routing & Browser Bypass: The mention of "firefox" routes execution
   away from the built-in fast CDP browser (`server/browser/`) to the OS desktop
   emulation surface because `server/surface.ts` only mounts the browser when
   `botOpened: true`. The fast path (DOM selection, CDP navigation) is withheld.
2. Banned Batch Actions: `server/computer-tool-list.ts` removes `run_steps` and
   `run_script` from CUA Driver 0.41.3. The model cannot chain "focus address bar +
   type URL + press Enter" in one turn; every atomic action is forced into an
   isolated LLM turn, expanding a 2-step task into 18–22 sequential roundtrips.
3. Gemini 3.8 Flash High Reasoning Inflation: At thinking level "high", Gemini
   Flash generates 1,500 to 4,000 internal chain-of-thought tokens per turn. For
   vision/desktop prompts with 62 tool schemas, Gemini spends 18–28 seconds per
   turn purely on reasoning generation. Over 18 turns, this accounts for 360–500
   seconds (6 to 8.3 minutes) in LLM inference time alone.
4. Coordinate Scaling & DPI/Retina Mismatches: Desktop screenshots captured by
   CUA driver or container screencasts are physical device pixels (e.g. 1920x1080 or
   Retina 2x 2880x1800). Input tools in CUA Driver 0.41.3 and `electron/lent-screen-tools.mjs`
   expect coordinates in OS logical points. When models predict click coordinates
   from physical images without scale translation, clicks land off-target. The address
   bar never gains focus, leading to repeated failed click attempts.
5. Rigid Argument Filtering: `electron/lent-screen-tools.mjs` strictly rejects any
   call with unlisted keys (e.g. `modifiers` on `click` vs `modifier`, or `coordinate: [x,y]`).
   When models produce standard variations, the call is rejected, burning entire turns.
6. Massive Screenshot Bloat: `server/container-computer.ts` captures unscaled,
   uncompressed 1080p PNGs (2.5MB–5.0MB base64) via `base64 -w0`, unlike
   `server/vps-computer.ts` which compresses images to JPEG quality 70 (80KB).
7. CUA Driver 0.41.3 Tool Schema Bloat: 62 tool definitions are injected into
   the system prompt on every turn, consuming ~18,000 prompt tokens per turn.
8. System Prompt Indirection: `server/system-prompt.ts` instructs models to
   perform pixel-based `get_window_state` before and after every action, and
   forbids direct CLI launches (e.g. `firefox <url> &`).


2. TURN-BY-TURN QUANTITATIVE LATENCY DECOMPOSITION
--------------------------------------------------------------------------------
When executed over the OS desktop via CUA Driver without batching or CDP tools:

Turn  1: Model calls `get_window_state` to inspect desktop / locate Firefox icon.
Turn  2: Model calls `click` on Firefox dock icon.
Turn  3: Settle delay + screenshot capture. Model calls `get_window_state` to confirm.
Turn  4: Coordinate mismatch: click missed or window delayed. Model calls `click` again.
Turn  5: Model calls `get_window_state` to find address bar coordinates.
Turn  6: Model calls `click` on address bar.
Turn  7: Model calls `type_text` "https://en.wikipedia.org".
Turn  8: Model calls `press_key` "Return".
Turn  9: Settle delay + screenshot. Model calls `get_window_state` to check Wikipedia load.
Turn 10: Model calls `get_window_state` with query "search".
Turn 11: Model calls `click` on Wikipedia search box.
Turn 12: Model calls `type_text` "World War I".
Turn 13: Model calls `press_key` "Return".
Turn 14: Settle delay + screenshot. Model calls `get_window_state` to check search results.
Turn 15: Model reads summary and returns final answer to user.

AVERAGE LATENCY PER TURN ON GEMINI 3.8 FLASH (HIGH):
- Prompt & 62 Tool Schemas (~18k tokens) serialization & upload : ~1.5s
- Uncompressed Screenshot Base64 encode & upload (2.5MB - 5MB)    : ~3.0s
- Gemini 3.8 Flash High Reasoning Phase (2,500 tokens @ 110 t/s) : ~22.7s
- Output Tool Call Token Generation                             : ~1.2s
- Node MCP Bridge Proxy & JSON-RPC Dispatch                      : ~0.4s
- OS Input Execution (xdotool / CUA driver)                      : ~0.6s
- Settle delay (`SCREEN_SETTLE_TIMEOUT_MS`)                     : ~1.5s
--------------------------------------------------------------------------------
Average Turn Latency: ~30.9 seconds / turn.

TOTAL TIME ACROSS 15 TURNS:
15 turns x 30.9 seconds = 463.5 seconds (~7.7 minutes).


3. DEEP-DIVE SUBSYSTEM ARCHITECTURAL FINDINGS
--------------------------------------------------------------------------------

3.1 CUA Driver 0.41.3 & Schema Bloat (server/computer-tool-list.ts, server/local-computer.ts)
---------------------------------------------------------------------------------------------
- CUA Driver 0.41.3 lists 62 tools on macOS and 66 on Linux (`server/computer-tool-list.ts:1`).
- Every tool carries comprehensive JSON schema parameters (e.g. `click` has 11 properties,
  `get_window_state`, `set_agent_cursor_motion`, `zoom`, etc.).
- Because all 62 tools are declared in the active tool manifest:
  * Gemini 3.8 Flash and OpenAI Chat drivers pass ~18,000 tokens of tool definitions in
    every single request payload.
  * In `server/local-computer.ts` (lines 6-17, 73-104), strict driver file identity keys
    (`DRIVER_FILE_IDENTITY_KEYS`: dev, ino, uid, gid, mode, size, mtimeNs, ctimeNs) verify
    the local binary, and `decodeLinuxDescriptor` enforces exact tool lists.
  * The sheer size of the tool registry slows model parsing and increases attention dispersal,
    leading the model to generate longer reasoning chains before selecting an action.

3.2 Surface Routing & Fast-Path Elimination (server/surface.ts, server/browser/)
--------------------------------------------------------------------------------
- In `server/surface.ts` (lines 61-84, `placeOf`):
  `const beside = input.botOpened === true && browserOn;`
  For user chat turns, `input.botOpened` is false or undefined.
  Consequently, `placeOf` outputs `{ computer: destination, browser: false, pinned: null }`.
- In `server/index.ts` (lines 8414-8424):
  `integrations.browser` is omitted because `plan.browser` is false.
- The repository contains an ultra-fast, headless CDP browser engine in `server/browser/`
  with tools `agent_browser_navigate`, `agent_browser_snapshot`, `agent_browser_fill`, and
  `agent_browser_click`.
- If routed through `server/browser/`:
  Turn 1: `agent_browser_navigate({ url: "https://en.wikipedia.org/wiki/World_War_I" })`
  Turn 2: Read DOM tree / summary. Done in < 6 seconds.
- But because the user typed "firefox", `server/system-prompt.ts` (line 328) commands:
  "A task that names Firefox uses the Firefox already open on this desktop."
  This binds the agent to the OS desktop container and forces pure pixel automation.

3.3 Action Batching Ban & Micro-Turn Expansion (server/computer-tool-list.ts)
-----------------------------------------------------------------------------
- In `server/computer-tool-list.ts` (lines 15-27):
  `const BATCH_RUNNERS: ReadonlySet<string> = new Set(["run_steps", "run_script"]);`
  Line 26 filters them out from the client tool list:
  `return !DRIVER_UPKEEP.has(name) && !BATCH_RUNNERS.has(name) ...`
- The rationale in comments was that each action should get its own approval.
- In practice, for autonomous computer use, this artificially fractures standard user workflows:
  * Clicking an address bar, typing a URL, and pressing Enter requires THREE separate LLM turns
    (plus 3 settle waits and 3 screenshot evaluations), adding ~90 seconds for a 50ms operation.

3.4 Gemini 3.8 Flash "High" Thinking Token Delays (server/drivers/antigravity-acp.ts)
-------------------------------------------------------------------------------------
- Gemini 3.8 Flash supports variable reasoning efforts (`low`, `medium`, `high`).
- In `server/drivers/acp/config-options.ts`, `acpVariantOption` maps `thought_level` / `effort`
  to variant choices.
- When set to `high`:
  * Gemini 3.8 Flash generates 1,500 to 4,000 reasoning tokens per turn before outputting
    the JSON tool call.
  * When presented with a full-desktop screenshot and 62 tool schemas, Gemini analyzes every
    visual region in detail: "The Firefox window is visible at top-left. The URL bar is located
    near coordinates (240, 80). Let me double-check the window title..."
  * Thinking latency alone is 20–28 seconds per turn.
  * Over 15–20 turns, `20 * 24s = 480s` (8 minutes).

3.5 Coordinate Scaling & Retina/DPI Target Misses (electron/lent-screen-tools.mjs)
---------------------------------------------------------------------------------
- Disconnect between screenshot pixel grid and OS input coordinate space:
  * Screencasts / `get_desktop_state` in CUA driver produce physical raster dimensions
    (e.g., 1920x1080 or 2560x1440 on macOS Retina).
  * `click`, `move_cursor`, and `drag` in `electron/lent-screen-tools.mjs` and CUA Driver
    expect logical coordinates (e.g. 1280x720 or 1440x900).
  * If a model sees the address bar at x=600, y=80 in a 1920x1080 image, but the logical
    desktop space is 1280x720 (scale factor 1.5x), passing {x: 600, y: 80} clicks at logical
    position 600 (which corresponds to physical 900), completely missing the address bar!
  * Result: Click lands on an inactive toolbar area. The address bar never receives focus.
  * The subsequent `type_text` types nothing into the browser.
  * The model is forced to call `get_window_state` again, re-evaluate, hypothesize why the
    click failed, and retry. This loop frequently adds 4 to 8 wasted turns (120–240 seconds).

3.6 Rigid Argument Filtering & Rejected Tool Calls (electron/lent-screen-tools.mjs)
-----------------------------------------------------------------------------------
- In `electron/lent-screen-tools.mjs` (lines 86-98):
  `for (const key of Object.keys(given)) {`
  `  if (!Object.hasOwn(allowed, key)) return { error: `${name}: ${key.slice(0, 100)} is not allowed on a lent screen` };`
  `}`
- Notice the schema discrepancies:
  * `click`: takes `modifier: KEYS` (singular).
  * `press_key`: takes `modifiers: KEYS` (plural).
  * Many LLMs (Gemini, Claude, GPT) intuitively pass `modifiers` to `click` (e.g. `modifiers: ["Control"]`),
    or pass `coordinates: [x, y]` instead of `{ x, y }`.
- When this happens, `lentScreenArguments` returns an immediate validation error.
- The model must take another turn to read the error and correct the argument structure.

3.7 Screenshot Latency & Payload Disparity (server/container-computer.ts vs vps-computer.ts)
--------------------------------------------------------------------------------------------
- Disparity between container and VPS computer implementations:
  * `server/vps-computer.ts` (lines 56-62):
    Uses Pillow to downscale screenshots to 1280x1280 and encodes to JPEG quality 70:
    `image.thumbnail((1280, 1280))`
    `image.convert("RGB").save(output, format="JPEG", quality=70)`
    Yields an efficient payload of ~70KB to 100KB.
  * `server/container-computer.ts` (lines 1048-1053):
    `["exec", target.containerName, "base64", "-w0", screenshot]`
    Directly streams unscaled, uncompressed 1080p PNGs.
    Yields 2.5MB to 5.0MB base64 per image.
  * Base64 serialization, Node buffer handling, HTTP transport, and LLM vision tile
    tokenization of multi-megabyte PNGs adds 4–6 seconds of pure transport overhead per turn.

3.8 Context Bloat, ACP Image Stripping & Vision Feedback (server/drivers/openai-chat.ts, acp/custom.ts)
-------------------------------------------------------------------------------------------------------
- In `server/drivers/openai-chat.ts` (lines 893):
  `dropStaleScreenshots(messages)` strips older screenshots, but only if they strictly start
  with `Screenshot result from tool call `.
- In `server/drivers/acp/custom.ts` (lines 14-30):
  `support.images: true` is missing.
  In `server/drivers/acp/core.ts` (lines 1449-1451):
  `const imageBlocks = support.images === true && runtimeAcceptsImages ? await readAcpImageBlocks(turn.images ?? []) : [];`
  Screenshots are stripped (`imageBlocks = []`). Custom ACP models (like Mistral vibe-acp)
  run completely blind, hallucinating desktop state and getting stuck in infinite click loops.

3.9 System Prompt Bias Toward Human-Like Pixel Hunting (server/system-prompt.ts)
--------------------------------------------------------------------------------
- In `server/system-prompt.ts` (lines 327-329, `SANDBOX_DESKTOP_INPUT`):
  "On this desktop, read a window with get_window_state before acting on it and take x,y
  from that window's own screenshot... If an accessibility type or click changed nothing,
  read that window again and type in the foreground..."
- In `server/surface.ts` (line 156, `SURFACE_AUTHORITY`):
  "Do not substitute the provider's own desktop, a shell-launched browser, or another
  automation path for the selected OpenBot surface."
- The model is explicitly trained and instructed NOT to use fast programmatic shortcuts:
  * It will NOT run `firefox "https://en.wikipedia.org/wiki/World_War_I" &` via `vm_exec`.
  * It will NOT use `launch_app` with `urls: ["https://en.wikipedia.org"]` (even though CUA 0.41.3 supports it!).
  * It insists on: Click Firefox -> Wait -> Click address bar -> Wait -> Type URL -> Press Return -> Wait.


4. RECOMMENDED ARCHITECTURE PATCHES (RANKED BY SPEEDUP)
================================================================================

Patch 1: Enable Action Batching (`run_steps`) for Computer Tools (Speedup: 4x-5x)
--------------------------------------------------------------------------------
Allow `run_steps` in `server/computer-tool-list.ts` so the model can chain address bar focus,
text entry, and Enter key submission into a single turn:
File: `server/computer-tool-list.ts`
```typescript
- const BATCH_RUNNERS: ReadonlySet<string> = new Set(["run_steps", "run_script"]);
+ const BATCH_RUNNERS: ReadonlySet<string> = new Set();
```

Patch 2: Screenshot Compression & Thumbnailing in container-computer.ts (Speedup: 2x)
------------------------------------------------------------------------------------
Adopt the Pillow downscaling pipeline from `vps-computer.ts` in `container-computer.ts`,
reducing image size from 4MB to ~90KB:
File: `server/container-computer.ts`
```typescript
- ["exec", target.containerName, "base64", "-w0", screenshot]
+ [
+   "exec", target.containerName, "sh", "-c",
+   `python3 -c '
+ import sys, io, base64
+ from PIL import Image
+ im = Image.open("${screenshot}")
+ im.thumbnail((1280, 720))
+ out = io.BytesIO()
+ im.convert("RGB").save(out, format="JPEG", quality=75)
+ sys.stdout.write(base64.b64encode(out.getvalue()).decode("ascii"))
+ ' 2>/dev/null || base64 -w0 "${screenshot}"`
+ ]
```

Patch 3: Surface Fast-Path for Web Tasks (Speedup: 10x-15x)
-----------------------------------------------------------
Mount `integrations.browser` alongside the computer surface whenever web research intent is
present, allowing the agent to use `agent_browser_navigate` directly instead of OS GUI clicks:
File: `server/surface.ts`
```typescript
- const beside = input.botOpened === true && browserOn;
+ const beside = browserOn;
```

Patch 4: Normalize Argument Schemas in lent-screen-tools.mjs (Fixes Tool Rejections)
------------------------------------------------------------------------------------
Accept common LLM argument aliases (e.g. `modifiers` on `click`, `coordinate: [x, y]`):
File: `electron/lent-screen-tools.mjs`
```javascript
// Normalize modifiers -> modifier, coordinates -> x, y before validation
if (given.modifiers && !given.modifier) {
  given.modifier = given.modifiers;
  delete given.modifiers;
}
if (Array.isArray(given.coordinate) && given.coordinate.length === 2) {
  given.x = given.coordinate[0];
  given.y = given.coordinate[1];
  delete given.coordinate;
}
```

Patch 5: Add `images: true` to Custom ACP Driver (Fixes Blind Models)
---------------------------------------------------------------------
File: `server/drivers/acp/custom.ts`
```typescript
const support: AcpSupport = {
  ...
+ images: true,
};
```

Patch 6: System Prompt Optimization for Direct Navigation (Speedup: 3x)
-----------------------------------------------------------------------
Instruct models to prioritize URL parameters in `launch_app` or keyboard shortcuts (Ctrl+L)
rather than sequential mouse pixel navigation:
File: `server/system-prompt.ts`
```typescript
- "A task that names Firefox uses the Firefox already open on this desktop."
+ "A task that names Firefox may launch URLs directly using launch_app with urls or hotkey ['Control', 'l'] followed by type_text, rather than searching for GUI icons."
```
